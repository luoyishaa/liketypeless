# 公开语料抽样规则

`make_manifest.py`、`extract_parquet_corpus.py`、`make_translation_manifest.py` 使用固定 SHA-256 排序种子 `20260924`。所有选择只来自官方 test，或 FLORES-200 的公开 devtest，不混入 train。相同文件及脚本版本会选出相同 ID；`prepare_audio.py` 在清单中记录原始和 16 kHz PCM16 音频 SHA-256，报告用不含本机路径的 manifest 哈希核对样本。

| 来源 | 当前目标 | 说话人规则 | 场景 |
|---|---:|---|---|
| AISHELL-1 test | 300 | 20 个 test 说话人，每人至多 15 条 | 干净朗读 |
| Common Voice 21 zh-CN test | 150 | 每位说话人至多 3 条 | 众包朗读 |
| FLEURS cmn_hans_cn test | 150 | 每个语料/朗读文本 ID 至多 3 条；原 TSV 无说话人 ID | 多领域朗读 |
| AISHELL-4 test | 150 | 大/中/小房间各一场；剔除与其他说话人重叠超过 0.1 秒的片段 | 远场会议诊断，单独报告 |
| WenetSpeech test_net/test_meeting | 待授权 | 两类分别抽样、单独报告 | 网络/会议语音 |

这些公开测试集还不能充分代表实时口语、重叠发言、远场噪声或长篇录音。不能将 WenetSpeech 未授权测试集或 Common Voice spontaneous 的单条无验证录音凑入当前基线。新增场景须新建独立分层，不能悄悄改变既有样本集。

## 短句诊断切片

从同一 Common Voice 21 zh-CN test 镜像筛选规范化参考长度为 1–4 字的录音，排除原 600 条基线中的全部 ID，再按同一固定排序选 100 条，每说话人最多 3 条。候选池为 552 条、499 位说话人。选择依据只有参考长度、说话人和 ID，不依据模型错误；它是刻意偏向短句的诊断切片，不与普通朗读基线混算，也不能代表真实语音命令分布。

高风险文字 32 条和日期关联验证 8 条为人工编写的开发回归集，不含真实录音，不计入 ASR CER。日期和同音姓名的自动词项检查是在发现问题后补充的回归约束，不是预注册的盲测指标。

本轮核对后修正了 FLEURS 字段名称：原适配器将第一列的语料 ID 误写为 `speaker`。同一 ID 可对应相同句子的男女声录音，因此不能用于说话人平衡或置信区间。新适配器输出 `corpus_id`；相同分组和排序选出的音频 ID 不变。本轮配对实验继续使用已冻结的旧清单维持哈希可比性，但分析工具明确不使用其 FLEURS `speaker` 字段，含 FLEURS 的总体也不报告说话人 bootstrap 区间。旧报告的 CER 本身不受元数据名称影响。
