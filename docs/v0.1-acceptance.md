# v0.1 桌面验证矩阵

未勾选的项目表示尚无验证结果。测试输入不得包含密码、验证码、客户资料或其他敏感内容。

## 基本功能检查

1. 运行 `liketypeless-Setup-0.1.0-rc.2.exe`，选择当前用户安装。未购买签名证书；若系统拦截，先核对来源与 SHA-256，不关闭安全防护。
2. 打开应用，首次使用选择官方来源下载模型；已有模型可从任意本地模型目录导入。
3. 等待“已校验”。到偏好设置选择麦克风，保留基础模式，不启用 Ollama。
4. 在首页点“在这里试录”，说“明天下午三点提醒我给李老师发邮件”，结束录音。最近结果应保留文字，能手动复制；这里试录不会向别的窗口写字。
5. 完成引导后从托盘退出并重新打开：日常启动应只显示托盘图标，大窗口可以从托盘“设置与最近结果”打开。打开记事本，点进空白文档，按录音快捷键，说一句话，再按一次。检查是否写入正确位置、有没有漏字。若 Shift+Space 与输入法冲突，改为 Ctrl+Shift+Space。
6. 在浏览器普通文本框和 Word 各重复一次。不要在密码框或正在编辑的重要文档中试。
7. 录音开始后关闭目标窗口，再结束录音。应保留最近结果，不向其他窗口写入。
   再试一次录音期间主动切到另一个窗口：程序应保留文字并提示手动复制，不应抢回原窗口。
8. 先复制一张图片，再试一次录音输入。应保留图片剪贴板，并出现小型恢复对话框供手动复制，不应自动打开大窗口。再复制一段普通文字重试，检查输入成功后原剪贴板文字是否恢复。
9. 模型准备好后断网试录；基础输入应该继续工作。重新联网后无需重新下载模型。
10. 从托盘退出，再打开；设置和最近文字应保留。关闭主窗口只是隐藏，不是退出。

缺陷记录字段：步骤、输入语音的参考文本、实际输出、目标窗口、停止录音到可用文字的耗时、界面提示。提交日志前应删除个人数据。

## 跨应用输入测试

在记事本、浏览器文本框、Word 中，各做以下 20 次，合计 60 次。每次用不同的自然表达，保留原始识别和最终文字；时间从第二次按快捷键开始，到文字实际可用为止。

| 每个应用的轮次 | 场景 | 预期 |
|---|---|---|
| 1–5 | 普通完整中文句子 | 自动输入正确位置 |
| 6–8 | 数字、日期、金额 | 原始与整理结果不能擅自改变事实 |
| 9–11 | 人名、地名、中英术语 | 记录识别错误，不替系统猜测 |
| 12–14 | 停顿、重说、第一第二 | 不丢有意义的内容 |
| 15–17 | 10–15 秒稍长表达 | 记录停止后的等待和遗漏 |
| 18–20 | 日常背景声音 | 记录准确度和人工修改量 |

正常路径要求至少 59/60 次直接完成；粘错窗口、无法恢复的结果丢失必须为 0。识别内容错误与“有没有输入到正确位置”分开计分。

额外故障测试不计入上述 60 次：目标关闭、焦点变化、图片剪贴板、剪贴板被更新、拔出麦克风、快捷键被占用、后台退出、模型下载中断、Ollama 未启动、GPU 不可用。失败后应有可理解的下一步，不能只剩“处理中”。

## 自然口述质量评估（30 条）

每类 5 条：日常安排；数字与日期；人名和地名；中英混说及技术名词；停顿与自我纠正；轻微背景噪声。每条建议 5–15 秒，采用自然表达而非逐字朗读固定脚本。

每条填写：编号、场景、参考文字、原始识别、整理后结果、事实是否变化、修改字符数、停止后的等待秒数、是否可以直接使用。

自动字错误率只对“实际说的话”和“原始识别”计算。整理后允许删掉无意义口头语，必须另审遗漏、编造、数字、人名和否定词，不能用一个相似度分数替代人工判断。

## 独立环境与安装维护

- [ ] Windows 11 x64，没有 Python、Node 或 Ollama，也能安装并启动。
- [ ] 中文用户名、含空格安装路径正常。
- [ ] 首次模型下载、断点重试和模型校验正常；模型就绪后离线输入正常。
- [ ] 连续 100 次麦克风录音处理无崩溃、卡死；合成音频循环单独计数。
- [ ] 20 次完整应用启动和退出无后台残留；后台单独启停测试不能替代这一项。
- [ ] 覆盖安装后设置和历史仍存在；卸载后没有运行进程。
- [ ] 用户数据留在 `%APPDATA%\liketypeless`，卸载不会默认删除个人结果。彻底清除可先在应用内清除记录，退出后再自行删除该目录中的配置和模型。
