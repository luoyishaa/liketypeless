# 0010. 长录音按本地 WAV 分块顺序转写

## 决策

`local-faster-whisper` 对超过可配置阈值的音频，在本地临时目录中切成连续 WAV 块后逐块转写。默认阈值和块大小均为 90 秒；设为 `0` 可关闭分块。

同一次请求只加载一次 Whisper 模型。每块结果的时间戳加回其原始音频偏移量，再按顺序合并；临时音频在请求结束后删除。

## 原因

一次性向本地 ASR 提交长录音会拉高等待时间和内存峰值，且异常时难以定位进度。按连续块处理使单次推理规模受控，又不需要引入常驻队列、额外服务或上传音频。

## 后果

- 短录音不改变：仍只进行一次推理，没有额外文件读写。
- 长录音的总耗时仍与音频时长相关，但单块失败更容易定位，且合并后的 segment 时间轴保持相对原录音的偏移。
- 当前第一版不重叠切块，避免重复文字和复杂去重。句子恰好跨越边界时，后续可在真实长录音评估后加入小重叠及去重策略。
- 仅支持 `soundfile` 可读取的本地音频；应用自身录音产物为 WAV，属于直接支持的格式。

## 验证

1. 使用大于 `LIKETYPELESS_STT_CHUNK_SECONDS` 的 WAV 调用 `/stt/transcribe`，确认返回完整拼接文本和递增的 segment 时间戳。
2. 将阈值设为 `0` 后用同一文件调用，确认仍使用单次转写。
3. 转写结束后检查系统临时目录，确认 `liketypeless-stt-*` 临时目录已清理。
