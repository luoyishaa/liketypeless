# 0011. 实时预览通过录音快照轮询实现

## 决策

主窗口在手动录音期间约每 3 秒请求一次当前音频缓冲区快照，转写后显示最新预览文本。预览不停止录音、不清空缓冲区，最终提交仍转写完整原始录音。

`local-faster-whisper` 用同一把进程内锁串行执行预览与最终转写，以避免共享模型实例并发推理导致不确定结果。

## 原因

真正的流式 ASR 需要维持增量解码状态、处理词语回滚和端点检测，超出当前本地 MVP 的必要复杂度。快照轮询能够在不新增服务、不上传音频的前提下提供可用的说话反馈，并保留稳定的最终批处理结果。

## 后果

- 预览文本是近似值，可能在下一次轮询或最终转写时修正；UI 不应把它当作最终输入。
- 预览快照在转写完成后立即删除，不会积累到录音目录。
- 当一次预览仍在进行时，最终转写会等待同一模型锁；这优先保证模型安全和最终结果的确定性。
- 当前全局快捷键模式以不干扰前台应用为先，只显示状态悬浮窗；可见的文本预览位于主窗口，后续可评估是否扩展到状态悬浮窗。

## 验证

1. 在主窗口开始录音并持续说话，确认约 3 秒后出现实时预览，且录音状态仍为 active。
2. 停止后执行最终转写，确认完整结果正常返回，且预览区域收起。
3. 连续触发预览和最终转写，确认没有并发模型错误，临时 `previews` 文件不会残留。
